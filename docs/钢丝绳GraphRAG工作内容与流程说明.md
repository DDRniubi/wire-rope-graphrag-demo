# 钢丝绳 GraphRAG 工作内容与流程说明

本项目已完成钢丝绳公开手册的知识建库，并将文档检索接入图像检测后的分析流程。输入一张钢丝绳照片，系统先用 YOLO 标出断丝候选位置，再利用千问描述图像；随后从手册知识图谱中找到相关检查知识和原文页，生成可查看来源的逐图报告。

本文说明已经完成的工作、各步骤的输入和输出，以及现有文件如何对应这些步骤。阅读本文后，可先查看实际结果，再按操作说明运行新图片。本文对应2026年10月16日的手册版本及完整演示包。

## 一 项目要解决什么问题

YOLO 能给出图中的候选位置和置信度，但检测框本身不能解释检查方法、缺陷机理或维护知识。为补充这部分信息，项目引入一本可追溯的钢丝绳专业手册，将其中概念与关系整理成图谱，用检测和图像描述作为检索条件，把找到的知识写入分析报告。

例如，图像中出现断丝候选框时，报告既展示框的位置，也可引用手册中“外层钢丝断丝属于目视检查内容”的说明。读者能够点击页码查看依据，而不是只看到一段无法追溯的模型文字。

## 二 目前已经完成什么

1. 获取并保存一份238页公开钢丝绳手册，记录来源地址和文件校验值。
2. 提取有实质文字的199页内容，保留原 PDF 页码，形成可建库文本。
3. 使用 Microsoft GraphRAG 完成实体、关系、社区和向量索引建设。
4. 制作图谱展示页及两组手册问答，提供原文页链接。
5. 将 YOLO、千问图像描述、图谱关系检索和逐图报告串联起来。
6. 在独立完整包中重新运行三张样例图，验证结果文件与来源引用，并做解压换目录运行检查。

这里的电子手册是取得的英文公开 PDF。项目生成的是它的分页文本、知识图谱、检索结果和分析报告，没有另行编写一本新的中文电子书。

整体工作分为两部分：先把手册建成知识库；之后每来一张新图，就使用现有知识库完成检测与分析。知识库无需随每张图片重复建立。

## 三 知识从哪里来 怎样整理

### 3.1 使用的原始资料

资料名称为《Wire Rope for Civil Works Structures》，编号 EM 1110-2-3200，由美国陆军工程兵团 USACE 发布，版本日期为2016年11月29日。文件共238页，涵盖钢丝绳结构、选型、失效、检查、润滑和维护等内容。

原始文件保存在 `source/EM_1110-2-3200.pdf`。来源网址、PDF页数、SHA-256校验值和每页提取记录保存在 `source_manifest.json`，用于核对索引与原文是否来自同一份资料。该资料用于通用检查与维护知识展示，其应用背景是 USACE 民用工程设施。

官方下载地址：
https://www.publications.usace.army.mil/Portals/76/Publications/EngineerManuals/EM_1110-2-3200.pdf

### 3.2 按页提取文字

第一步，由 `prepare_document.py` 读取 PDF，逐页提取文字，整理空格和连续空行。第二步，保留文字量达到200个字符的页面，并在文本开头写明资料名称、PDF页码和总页数。第三步，将每页保存成独立文本，例如 `input/usace_wire_rope_page_121.txt`。

最终保留199页，39页因文字量不足未进入文字索引。原始238页 PDF 完整保留。这个处理主要用于去掉封面、空白或很短的页面；它不会自动理解图片、示意图和扫描页，因此不能把199页文本索引理解为对全部238页图文的完整识别。

### 3.3 为什么要保留原页码

后续每条图谱关系关联到它来自的文本块，文本块又能关联回分页文档。这样可以沿“关系 → 文本块 → 文档 → PDF页码”找到原文。报告中的 `[P121]` 指实际 PDF 的第121页，不一定与纸面印刷的章节页码相同。

这一阶段的输入是一份 PDF，输出是199份文本文件和一份来源记录。此时尚未调用 YOLO，也没有对现场图像作判断。

## 四 如何把手册建成知识图谱

### 4.1 切成适合模型处理的文本块

GraphRAG 读取分页文本后，按照每块约450个 token、相邻块重叠50个 token 的设置切分。token 是模型处理文字的计量单位。重叠区域有助于保留段落前后联系，避免一个概念的说明恰好在分块处被截断。

这次建库形成321个文本块。块数比分页文档数多，是因为较长页面可能被拆成多个块。

### 4.2 抽取实体和关系

程序通过百炼调用 `qwen-plus`，从文本块中提取钢丝绳、缺陷、成因、检查方法、维护措施、规程和设备等概念。概念构成图谱节点；概念之间的关联构成边。例如，检查方法可以关联检查对象，损伤机理可以关联缺陷现象。

图谱关系是模型从文档中抽取并汇总的检索线索。关系描述本身可能有概括或偏差，所以逐图报告还要返回原文核对，不能直接把每条抽取关系当作已审核的事实。

### 4.3 划分社区并生成摘要

GraphRAG 将关联较紧密的概念分成社区。可把社区理解为图谱中围绕某个主题聚集的一组节点，如检查或润滑相关知识。随后生成社区报告，概括这些节点和关系。社区不是新增的资料来源，也不是人工标签。

### 4.4 生成并保存向量

程序调用 `text-embedding-v4`，把实体描述、文本块及社区内容转换成向量并存入 LanceDB。向量是便于计算文本相似性的数字表示。向量随索引保留，但当前逐图检索使用下面介绍的关系排序方法，不会在每张图运行时调用向量模型。

| 本次索引项目 | 实际数量 |
|---|---:|
| 分页文档 | 199 |
| 文本块 | 321 |
| 实体 | 1796 |
| 关系 | 2741 |
| 社区及对应社区报告 | 各349 |

配置位于 `settings.yaml`，建库提示词位于 `prompts/`，索引表和向量数据位于 `output/`。这些数量来自实际索引文件。展示网页只取部分节点和关系绘图，屏幕上显示的节点数不是全库规模。

## 五 已有知识库怎样用于检索和问答

### 5.1 从图像描述形成检索主题

逐图流程默认使用“可见断丝”和“疲劳”两个主题。描述出现油污、污染或润滑等词时，再增加润滑主题；检测难度为中或高，或没有检出候选框时，再增加内部检查主题。这里采用的是项目规则映射，不是根据一张照片确认了疲劳成因。

各主题对应英文检索词，例如 broken wire、inspection、fatigue、lubrication。代码位于 `graph_retrieval.py` 和 `integrate_detection_run.py`。

### 5.2 从实际图谱关系中排序

程序读取 `relationships.parquet`，比较检索词与关系两端的实体名称及关系描述。每个词命中实体名称加5分；未命中名称但命中描述加1分，再加入一小部分关系权重。去除重复实体对后，选出最多4条关系。

逐图报告的候选来源目前限定在已核对的 PDF 第78、80、121、130、131、136页。整本手册的图谱仍保留，但不能据此声称逐图报告已经自由利用了全部章节。

### 5.3 沿关系取回原文

关系记录保留文本块 ID，程序利用文本块和分页文档的对应关系找到来源页，再根据检索词在原文中的出现情况选择最多4页。报告保留选中的关系 ID、实体名称、来源页和原文，便于读者核对检索过程。

### 5.4 千问如何生成逐图分析

当前逐图报告采用受约束的生成方式：程序事先在上述原文中核对了目视检查、反复弯曲疲劳、无损检测局限、润滑作用四类事实条目。只有当相应原文页被检索到，才把条目作为候选依据送给 `qwen-plus`。

千问整理图像结果，并从候选条目中选择1至3个事实 ID。程序检查返回格式、候选框数量和事实 ID，再将固定的原文核对表述与页码写入报告。这样避免模型把无损检测的局限改写成目视检查的局限。实际请求及选择记录保存在逐图 `traces` 文件中。

本版本使用 Microsoft GraphRAG 的真实索引和项目自编关系排序，没有调用其默认 local/global search 查询接口；社区报告和向量索引暂未参与逐图答案排序。

### 5.5 文档问答展示

`run_questions.py` 另外生成两组手册示例问答：断丝疲劳与检查重点，以及表面检查、内部检测与润滑作用。`demo_artifacts/index.html` 展示的是已生成答案和来源。该页面尚未提供自由输入问题的在线聊天框。

## 六 怎样接入照片检测后的完整流程

### 第一步 读取新图并运行 YOLO

完整包将输入图片复制进本次结果目录，然后加载本地 YOLO 权重。默认使用现场断丝模型 `site_broken_wire_det_v6_hnm2`，输出标框图、候选框坐标和置信度。另附 DBTT 预训练权重；切换后只取断丝类别0，避免把其他类别写成断丝。

### 第二步 调用千问描述标框图

启用在线模式后，`qwen3.5-omni-flash` 接收 YOLO 标框图与框数、位置提示，描述环境、钢丝绳方向、表面状态、光照和候选区域可见性。框来自 YOLO，视觉模型负责补充描述。程序保存提示词、原始返回和结构化描述。

### 第三步 形成图像事件

程序合并检测坐标和视觉描述，为每张图形成结构化记录，包括图像名称、候选框数量、框坐标等。同时生成检测专用 Word 报告，供查看图片与检测位置。这个 Word 报告本身不包含后面的 GraphRAG 分析。

### 第四步 检索手册关系与原文

使用图像描述形成主题，按第五节的方法选出图谱关系，定位手册原文页。图像不会直接变成手册知识；它提供检索条件，手册提供检查知识依据。

### 第五步 生成带来源的逐图报告

调用 `qwen-plus` 整理图像结果并选择原文核对条目，程序写入引用页码，输出逐图 Markdown 报告和完整检索记录。

### 第六步 汇总并检查输出

生成 `complete_demo.html`，把标框图、视觉描述、图谱关系、分析、PDF和检索记录放在同一页面。随后检查图像与事件是否对应、关系 ID 是否存在于索引、引用是否来自检索页、PDF校验值是否一致、页面链接是否有效。

完整路径为：原图 → YOLO框 → 千问视觉描述 → 图像事件 → 手册关系检索 → PDF原文 → 千问选择依据 → 逐图报告与综合页面。

## 九 完整包如何运行

### 9.1 运行一张新图的完整流程

`graphrag_manual_demo` 是手册子工程，原入口仍依赖原项目其他目录及运行环境。独立运行使用另行整理的 `wire_rope_full_demo_20261016` 完整包，其中集中包含 YOLO 权重、检测代码、手册知识库与统一入口。

在完整包目录，首次安装依赖：
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup_env.ps1
```

设置自己的百炼 Key 并运行新图：
```powershell
$env:DASHSCOPE_API_KEY = '自己的API Key'
powershell -NoProfile -ExecutionPolicy Bypass -File .\run_full_pipeline.ps1 -InputPath data\input_images -Device cpu -UseQwen
```

先把图片放进 `data/input_images`。运行后打开终端显示的 `complete_demo.html`。首次安装联网下载依赖；带 `-UseQwen` 会调用视觉和文本 API，不带该参数只运行本地检测、检索及离线报告框架。

### 9.2 各阶段成果放在哪里

完整包的 `models` 放本地权重，`detection` 放检测代码，`knowledge` 对应本手册工程，`data` 放输入图片，`runs` 放每次运行的输出。结果中的 `detection` 看框和检测报告，`document_graphrag/reports` 看文档分析，`document_graphrag/traces` 看检索与生成过程。

后续如需扩展为自由问答、更多章节知识或运维决策，应继续扩展检索与事实条目、补充适用资料和评价数据。上述内容是当前已经实现的流程范围，可据此检查现有文件和演示结果。
